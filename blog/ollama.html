Ollama in 6 Commands for Developers: Run a Local LLM and Avoid Pitfalls

By Hector Gras · 21 September 2026 · updated 10 October 2026

Ollama is a free, open-source tool (MIT licence) that downloads and runs language models such as Gemma, Qwen and gpt-oss on your own computer. You use it from the command line, from its desktop app, or through a local API that other programs can call. Six commands cover most of what you'll do day to day: pull, run, list, show, ps and rm.

It's a good choice if you're comfortable in a terminal and want private, offline access to open models without paying per token. It's the wrong choice if you need the strongest reasoning available, or if your PC doesn't have the memory for the model you want.

What Ollama is

Ollama bundles a model engine, a library of ready-to-download models and a background service. Models are named like Docker images, name:tag, so gemma3:4b means Gemma 3 with 4 billion parameters. The default tags are already quantized (compressed) so they fit on ordinary hardware; LLM quantization explains what that means.

Ollama also offers cloud models, for ones too big for your machine. Those run on Ollama's servers and need an Ollama account, so your prompts leave your PC. Local models don't.

Install it and run your first model

Download the installer for Windows or macOS from ollama.com, or use the install script on Linux. The installer also sets up the background service that the app and the API talk to. Then, in a terminal:

  1. ollama pull gemma3:4b downloads a model. Check its size on the library page first; a 7B model is typically 4 to 5 GB.
  2. ollama run gemma3:4b starts a chat in the terminal, pulling the model first if you skipped step 1. Type /bye to leave.
  3. ollama list shows the models you've downloaded and how big they are.
  4. ollama show gemma3:4b prints details such as parameters, context length and licence.
  5. ollama ps shows which models are loaded in memory right now. ollama stop gemma3:4b unloads one.
  6. ollama rm gemma3:4b deletes a model and frees the disk space.

If a pull fails, a full disk is the usual cause. Start with a small model to check that everything works before you download a big one.

Picking a model that fits your PC

The number in the tag is the parameter count in billions, not the file size. What matters is whether the model fits in memory, ideally in your graphics card's own memory (VRAM), where it runs much faster. A rough guide for the default 4-bit versions:

Model sizeWhat it needs
1B to 4BRuns on most laptops with 8 GB of RAM, no graphics card needed
7B to 9B16 GB of RAM is comfortable; a graphics card with 8 GB makes it much faster
12B to 20BBest with a 12 GB or bigger graphics card (OpenAI says gpt-oss-20b runs with about 16 GB of memory)
70B and upNot practical on most home PCs

Two models with the same size tag can still need different amounts of memory, and long conversations need more on top, so check the listed size. There's more detail in how much VRAM you need for AI.

Using the API

The background service listens on http://localhost:11434. The main endpoints are /api/chat for conversations, /api/generate for single prompts and /api/tags to list installed models. There's also an OpenAI-compatible endpoint under /v1, so code written for OpenAI's chat completions format often works after you change only the base URL. A minimal call from Python:

import requests
r = requests.post("http://localhost:11434/api/chat", json={
    "model": "gemma3:4b",
    "messages": [{"role": "user", "content": "Explain recursion in two sentences."}],
    "stream": False,
})
print(r.json()["message"]["content"])

That's why Ollama is a common back end for coding assistants, scripts and agent tools that need a local model. It also runs in Docker. By default the API only listens on your own machine. If you open it to a network, put authentication in front of it, because Ollama's API doesn't check who is calling.

Day-to-day habits

The service keeps running in the background (on Windows you'll see it in the system tray). After you use a model it stays in memory for about five minutes by default, so the next answer starts quickly, and then it unloads. If you need the memory back sooner, use ollama stop or set keep_alive in your API calls. On battery, quit the service when you're not using it.

Models add up quickly on disk. Run ollama list now and then and remove what you no longer use.

Where Ollama fits, and where it doesn't

Ollama is good for private notes, offline coding help, local automation and trying lots of open models. A 7B or 13B model on a laptop won't match the big cloud AIs on hard reasoning, and on modest hardware it can be slow. It's also a developer tool at heart: there's a chat window now, but choosing models, sizes and settings is still up to you. Questions

What Exactly Does Ollama Do?

It downloads open models and runs them on your computer, through a command-line tool, a desktop app and a local API. You can chat with a model directly or call it from your own scripts.

What Is Ollama vs ChatGPT?

ChatGPT is a cloud service: your messages go to OpenAI's servers. Ollama runs models on your own hardware, so local chats stay on your PC and cost nothing per message. The trade-off is that the models you can run at home are smaller and less capable than the one behind ChatGPT.

Is Ollama Fully Free?

Ollama itself is free and open source under the MIT licence, and running local models costs nothing beyond your electricity. Its cloud models need an Ollama account and come with their own terms.

What Are the Disadvantages of Ollama?

Bigger models need a lot of memory, local models trail the top cloud AIs on hard reasoning, and you manage models, disk space and settings yourself, mostly from a terminal. The background service also uses memory while a model is loaded.
