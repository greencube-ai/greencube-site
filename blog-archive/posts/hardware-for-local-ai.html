For local AI, buy memory first and speed second. What decides which models you can run is whether your graphics card's memory (VRAM), or a Mac's unified memory, can hold the model plus the conversation it's working on. Roughly: 8 GB runs small 7B-class models, 16 GB runs 13B to 20B models comfortably, 24 GB runs 30B-class models, and 70B models need two big cards or a Mac with a lot of memory. Small models also run with no graphics card at all, just more slowly.

The tiers

"Local AI" means very different things to someone summarising PDFs on a laptop and someone running a 32B coding model all day. These four tiers cover most people. All sizes assume 4-bit quantization, the usual way models are shrunk to run at home.

A used 24 GB card is a sensible upgrade if you're serious, because memory, not raw speed, is what lets you run the next size up. Multi-GPU builds add real complexity (drivers, PCIe lanes, software that splits a model across cards), so most people are better off with one bigger card first.

How much memory a model actually needs

Start with the weights. At 16-bit precision each parameter takes 2 bytes, so a 7B model needs about 14 GB just to load. At 8-bit that halves to about 7 GB, and at 4-bit (the common GGUF builds) it's about 4 GB.

Model size16-bit8-bit4-bit
7B~14 GB~7 GB~4 GB
13B~26 GB~13 GB~7 GB
32B~64 GB~32 GB~18 GB
70B~140 GB~70 GB~40 GB

Weights are the floor, not the total. The model also needs room for its working memory of the conversation (the KV cache), which grows with the length of the context: double the context and that part roughly doubles. That's why a model that fits fine on a short chat can run out of memory on a long document. A rough rule is to take the 4-bit weight size, add a third to a half for the cache, plus a couple of GB for the runtime. If the total is more than your VRAM, use a smaller quantization, a smaller model, or let part of it run from system RAM (slower). More in how much VRAM you need and LLM quantization.

Apple Silicon or NVIDIA

Macs with Apple Silicon share one pool of memory between the processor and the graphics, so a Mac with 64 GB can give much of it to a model, more than any consumer graphics card at that price. They're quiet and efficient. The limits: you can't add memory later, and the Mac tools (such as MLX) differ from the CUDA ecosystem most AI software targets first.

NVIDIA cards have the broadest software support, from llama.cpp to server tools like vLLM, and you can upgrade the card or add a second one later. AMD and Intel cards are cheaper per GB and work with llama.cpp, but support for the newest tools tends to arrive later. If you want one quiet box for chat and documents, a high-memory Mac is appealing. If you want to grow over time, a PC with an NVIDIA card gives you more room.

CPU, RAM and storage

  • System RAM: about double your VRAM is comfortable, so 32 GB or more next to a 16 GB card. With less, anything that spills out of the card ends up swapping.
  • CPU: if a graphics card does the work, a mid-range 6 to 8 core processor is plenty. Without a card, the CPU and especially memory bandwidth decide your speed.
  • Storage: a fast NVMe SSD with room for several models. Files run from a few GB to 40 GB each, and a slow drive makes every model switch slow.
  • Power and cooling: AI runs keep the card busy for long stretches, unlike gaming. An undersized power supply or poor airflow shows up as random crashes or slowdowns that look like software bugs.

Which software suits which machine

llama.cpp is the engine under much of local AI and the best option for machines without a card or with little memory. Ollama wraps it in simple commands and works on almost anything. LM Studio adds a graphical app for downloading and chatting with GGUF models (see Ollama vs LM Studio). vLLM is for NVIDIA workstations serving many requests at once, not for a single laptop.

When a model runs out of memory

Before buying hardware, try these in order: shorten the context length, use a smaller quantization (4-bit instead of 8-bit), move fewer layers onto the graphics card so the rest runs from system RAM, or pick a smaller model. Read past the first line of the error log; it usually says whether loading the model or allocating the context failed. Only if none of that works is it time for a bigger card.
